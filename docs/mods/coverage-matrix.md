check, not a claim that a particular command has just run. Local/remote results
belong in the change's validation report. Tests use the real parser, reducer,
Simulator, save codec or multiplayer World; a second simulation is not an oracle.

## Evidence required for an official conversion

For each challenge, compare independently captured old behavior with the shared
interpreter using identical setup, seed, difficulty, legal strategy and explicit
responses. Keep golden hashes unchanged. Reached assertions must cover every
phase, option, selector/onset neighbor and expiry, including all five difficulties
and seeded ranges. An early-ending bot is partial evidence, not proof that later
rules match.

Compare monthly energy/finances/emissions/customers, complete setup and identity,
dates/effects/targets/receipts/loads, common goal verdicts and reasons, and recorded
review facts. Exercise live and catch-up ticks, forecast workers, headless runs,
pre/post-decision and target saves, official replay, and two-company worlds.
Temporarily changing an event month, selector or transfer must make the owning
comparison fail for the intended reason; restore the mutation afterward.

The first fully declarative official pilot is Load Shedding (`113`). Its bounded
[legacy phase parity fixture](../../src/testing/LoadSheddingLegacyParity.sim.test.tsx)
retains independently captured old facts; the [live boundary suite](../../src/reducers/LoadSheddingRules.test.tsx)
checks every difficulty's setup, strong/weak/unavailable phase contexts, opening
and catch-up ticks, worker transport, saves/replay and hostile receipts. The
[native two-company World](../../src/multiplayer/LoadSheddingWorld.sim.test.tsx)
reaches all five phases through the full 2022 goal window in both 84-month
companies and resumes a native-codec month-36 checkpoint. Pilot boundary tests
also reject forged active copy and preserve receipts beyond the rolling
2,400-entry regional journal bound. The
remaining official callback migrations are a separate increment; the existence
of a generated arc row is not evidence of a completed official conversion.

## Maximum-content measurements

Follow [the performance plan](../perf-plan.md). Measure the permitted 100 authored
events, 32 choices, 16 goals and 1200-month observations: cold/warm compilation,
plain/Immer tick and rollover, actual worker serialization, co-op world and save
bytes. `npm run perf:bench` and production `npm run perf:bundle` provide the normal
benchmarks/ceilings. The explicit maximum-content harness is
`npm run perf:bench -- --mods --runs 1 --json`; its
[fixture](../../src/testing/ModPerfFixtures.ts) and
[measurements](../../src/testing/ModPerfBench.tsx) exercise actual owning APIs.
Report measured limits and workloads; functional fake-clock
browser tests are not wall-time performance measurements. Never raise a ceiling,
weaken a goal or update a golden snapshot merely to obtain a pass.
