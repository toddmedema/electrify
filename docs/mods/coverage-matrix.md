# Mod verification map

Use this map to find tests for a behavior you are changing. It covers the parser,
compiler, simulation, saves, Workshop and co-op. Test results belong in the PR's
validation notes.

## Official challenge regressions

Compare changes against independently captured behavior using the same setup,
seed, difficulty, strategy and responses. Cover every phase and branch, onset and
expiry, forecasts, saves/replay and two-company worlds. A run that ends early
cannot verify a later event. Keep reference fixtures unchanged unless the intended
behavior changes, and confirm that a deliberate rule violation fails the owning
check.

## Performance

Follow the [performance plan](../perf-plan.md). Run the maximum-content workload with:

```sh
npm run perf:bench -- --mods --runs 1 --json
```

The [fixture](../../src/testing/ModPerfFixtures.ts) and
[benchmark](../../src/testing/ModPerfBench.tsx) cover compilation, ticks, rollovers,
worker transport, co-op and save sizes through 1,200 months. Keep the ordinary
`perf:bench` ratio gates and production `perf:bundle` byte limits as separate checks.
Browser tests with fake clocks do not measure wall-clock performance.
