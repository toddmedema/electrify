# Challenge compatibility

Friend challenges name a scenario, seed, difficulty and the current simulation rules.
Saves, challenges and replays from different rules are rejected instead of rewritten.
`src/data/RunCompatibility.json` records a SHA-256 content identity, generated by
`npm run compatibility:generate`. The manifest is git-ignored; the npm pre-hooks of
start, build, test, sim and typecheck regenerate it from the current sources.

The generator hashes the explicit rules revision, relative filenames and content
digests of:

- Simulation data, helpers and reducers under `src/data`, `src/helpers` and
  `src/reducers`, excluding tests and the generated manifest itself.
- Shared constants, domain types and the exact dependency lockfile.
- All shipped weather binaries, data indexes and economic/fuel CSVs under
  `public/data`.

Text line endings are normalized to LF; binary bytes are hashed unchanged. Files
are sorted by path. An input that is only a Git LFS pointer is rejected.

This deliberately broad set changes after harmless helper or type edits. It gates
run identities, challenge links and replay headers without maintaining a duplicate
list of individual simulation formulas. Because inputs are selected by directory,
keep interface-only content under `src/components` rather than `src/data`.
No historical simulation runtime or save upgrade path is provided; see [save formats](saves.md).

Steam leaderboard names derive from `compatibilityId`, so code that only co-op runs stays
out of it. The manifest's separate `multiplayerCompatibilityId` hashes `compatibilityId`
together with `src/multiplayer`, the co-op worker and the native Steam transport. Co-op
lobbies and shared saves require it to match, so peers reject incompatible message formats
and simulation builds before joining, without moving single-player leaderboards.

When changing simulation behavior outside these directories, add the source to
the generator's inputs, or bump `rulesRevision` in the generator.
Changes to the digest algorithm or input-selection policy also require a rules
revision bump. Authored references carry the scenario, seed, difficulty and this
single compatibility digest. Only current reference and invitation shapes with a
matching digest are accepted.

The manifest also includes per-file fetch integrity metadata. Browser CSV and
weather loads verify the actual response bytes, including offline-cache responses,
against the build's expected SHA-256. A mismatched response uses the existing
loading-error path instead of initializing a falsely equivalent run. Shipped text
data must use LF line endings, as enforced by `.gitattributes`; the generator
rejects CRLF data so integrity metadata remains portable across build platforms.

The manifest represents the data shipped with this build. Deployment must publish
application code and its matching `public/data` together; it must not replace
simulation data independently under an already-published build.
